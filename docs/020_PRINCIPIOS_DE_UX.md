# NEXAI
# 020 - Principios de UX

> **Versión:** 1.0
> **Estado:** Activo
> **Prioridad:** Obligatorio

---

# Objetivo

Definir los principios de experiencia de usuario que deberán respetarse durante todo el desarrollo del frontend.

La experiencia de usuario tiene la misma importancia que el código.

Una aplicación técnicamente perfecta puede fracasar si la experiencia no es agradable.

---

# Filosofía

La interfaz debe desaparecer.

El usuario nunca debe pensar en la aplicación.

Debe concentrarse únicamente en lo que quiere hacer.

La mejor interfaz es aquella que casi pasa desapercibida.

---

# Menos es más

No agregar componentes únicamente porque existe espacio disponible.

Cada elemento debe tener un propósito.

Si un elemento no aporta valor, deberá eliminarse.

---

# Una sola acción principal

Cada pantalla debe tener una acción principal claramente identificable.

El usuario nunca debe preguntarse:

"¿Qué hago ahora?"

---

# Reducir fricción

Toda acción importante debe realizarse con la menor cantidad posible de pasos.

Menos clics.

Menos ventanas.

Menos confirmaciones.

---

# Consistencia

Si un componente funciona de cierta manera en una pantalla,

deberá funcionar exactamente igual en el resto del proyecto.

Nunca sorprender al usuario.

---

# Jerarquía Visual

El usuario debe identificar inmediatamente:

- Qué es importante.
- Qué es secundario.
- Qué puede ignorar.

La jerarquía debe lograrse mediante:

- Espacio.
- Tamaño.
- Tipografía.
- Color.

Nunca utilizando demasiados elementos.

---

# Espacio

El espacio vacío forma parte del diseño.

No intentar llenar toda la pantalla.

El contenido necesita respirar.

---

# Tipografía

La tipografía comunica más que los colores.

Debe existir una jerarquía clara.

No utilizar muchos tamaños distintos.

No abusar de negritas.

---

# Colores

El color debe utilizarse para comunicar.

No para decorar.

Un color pierde valor cuando todo tiene ese color.

---

# Feedback

Toda acción debe generar una respuesta inmediata.

El usuario debe saber que la aplicación recibió su interacción.

---

# Errores

Nunca culpar al usuario.

Los mensajes deben ser claros.

Siempre ofrecer una solución.

---

# Velocidad

La aplicación debe sentirse rápida.

Aunque una operación tarde algunos segundos,

la interfaz nunca debe sentirse congelada.

---

# Animaciones

Las animaciones ayudan a comprender la interfaz.

No existen para llamar la atención.

Nunca retrasar al usuario.

---

# Lectura

El chat será el elemento más utilizado.

Debe poder leerse durante horas.

Por ello:

- Buena separación.
- Excelente contraste.
- Longitud de línea cómoda.
- Mucho espacio.

---

# Fatiga Visual

Evitar:

- Colores fuertes.
- Fondos brillantes.
- Sombras exageradas.
- Glow constante.
- Interfaces saturadas.

NEXAI debe sentirse cómodo incluso después de varias horas de uso.

---

# Descubrimiento

Las funciones importantes deben ser fáciles de descubrir.

Las funciones avanzadas pueden permanecer ocultas hasta ser necesarias.

No mostrar todo al mismo tiempo.

---

# Acciones Destructivas

Las acciones que eliminen información deberán distinguirse claramente.

Nunca colocarlas junto a acciones frecuentes.

---

# Carga Cognitiva

Reducir la cantidad de decisiones que el usuario debe tomar.

La interfaz debe ayudar.

No complicar.

---

# Elegancia

La elegancia no consiste en agregar elementos.

Consiste en eliminar todo aquello que no aporta valor.

---

# Principio Final

Cada decisión de UX deberá responder una pregunta:

> ¿Esto hace que trabajar en NEXAI sea más fácil y agradable?

Si la respuesta es no,

la implementación deberá replantearse.
