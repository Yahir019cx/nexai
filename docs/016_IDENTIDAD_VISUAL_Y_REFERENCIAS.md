# NEXAI
# 016 - Identidad Visual y Referencias

> **Versión:** 1.0
> **Estado:** Activo
> **Prioridad:** Obligatorio

---

# Objetivo

Este documento sirve como guía visual para mantener una identidad consistente durante todo el desarrollo.

Claude Code deberá utilizar estas referencias como inspiración.

No deberá copiarlas.

La intención es comprender el estilo visual que buscamos.

---

# Filosofía

NEXAI debe sentirse como un software premium.

No como una aplicación desarrollada rápidamente.

El usuario debe percibir calidad desde el primer segundo.

---

# Palabras Clave

Toda interfaz deberá transmitir:

- Elegancia
- Tecnología
- Simplicidad
- Precisión
- Fluidez
- Minimalismo
- Sofisticación
- Profesionalismo

---

# Lo que buscamos

Interfaces limpias.

Mucho espacio visual.

Excelente jerarquía.

Componentes propios.

Microanimaciones.

Transiciones suaves.

Colores utilizados con moderación.

Fondos vivos pero discretos.

---

# Lo que NO buscamos

Interfaces recargadas.

Gradientes exagerados.

Neones.

Glow excesivo.

Bordes de colores.

Sombras enormes.

Botones gigantes.

Animaciones llamativas.

Componentes infantiles.

---

# Inspiración General

Tomar inspiración de productos como:

- Linear
- Raycast
- Arc Browser
- Vercel
- Notion
- Apple
- Warp
- Perplexity

La inspiración es únicamente visual.

Nunca copiar componentes.

Nunca copiar layouts completos.

Nunca copiar la identidad de otro producto.

---

# Sidebar

Debe sentirse ligera.

Elegante.

Con excelente separación.

Mucho espacio entre elementos.

Hover suave.

Blur ligero.

Nunca saturada.

---

# Chat

Debe ser el protagonista.

Mucho espacio.

Excelente lectura.

Nada comprimido.

El usuario debe poder leer durante horas sin fatiga visual.

---

# Prompt

Debe sentirse como una herramienta profesional.

No como un TextField.

Debe integrarse perfectamente con el resto del producto.

---

# Tarjetas

No deben parecer cajas.

Deben sentirse ligeras.

Con profundidad.

Sin sombras exageradas.

---

# Botones

No utilizar botones enormes.

No utilizar colores fuertes.

El botón principal debe destacar únicamente cuando sea necesario.

---

# Animaciones

Microanimaciones.

Nunca animaciones de espectáculo.

Todo movimiento debe sentirse natural.

---

# Partículas

El fondo podrá contener partículas.

Las partículas deberán ser:

- pequeñas
- elegantes
- lentas
- discretas

Nunca convertirse en el centro de atención.

---

# Conexiones

Podrán existir líneas entre partículas.

Muy sutiles.

Con baja opacidad.

Nunca formar patrones excesivamente complejos.

---

# Fondo

El fondo nunca debe estar completamente muerto.

Siempre deberá existir una ligera sensación de vida.

Puede lograrse mediante:

- partículas
- iluminación
- desenfoques
- movimiento extremadamente lento

---

# Espaciado

La calidad visual de NEXAI dependerá en gran medida del espacio.

No llenar la pantalla.

No intentar aprovechar cada píxel.

El espacio vacío también comunica calidad.

---

# Jerarquía

El usuario siempre debe saber:

Qué es importante.

Qué es secundario.

Qué puede ignorar.

Nunca competir visualmente entre componentes.

---

# Consistencia

Todos los módulos deberán parecer diseñados por el mismo equipo.

Nunca improvisar estilos nuevos.

Si un nuevo componente rompe la identidad visual, deberá rediseñarse.

---

# Moodboard

Este documento podrá contener imágenes de referencia.

Cada imagen deberá incluir:

- Qué nos gusta.
- Qué no nos gusta.
- Qué elementos queremos adaptar.
- Qué elementos nunca debemos copiar.

No se trata de copiar diseños.

Se trata de construir una identidad propia.

---

# Regla Final

La inspiración debe servir para construir una identidad.

Nunca para reemplazarla.

El objetivo final es que, al ver una captura de pantalla, cualquier persona pueda reconocer inmediatamente que pertenece a NEXAI sin necesidad de ver el logotipo.
